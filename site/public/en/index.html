Portfolio project

Climate survey and eNPS analysis with AI, without exposing anyone

Voz sem nome removes names, documents and contact details from survey comments before any model reads the text. Then a language model groups the comments by theme, measures sentiment and flags cases that need HR attention, such as harassment and burnout. The demo runs on Cloudflare. The same system can also run entirely on the company's own server.

Try the demo See the dashboard

The problem

In a climate survey, the score says little. The reasons are in the open comments, and someone has to read them one by one.

  1. Manual reading

    Reading, sorting by theme and counting comments takes HR days in every cycle. With hundreds of answers, the analysis arrives late.

  2. Privacy risk

    Comments mention coworkers, managers, branches and sometimes a phone number or email. Whoever reads them learns who is being discussed, and a small slice of data can reveal who answered.

  3. Serious signals get lost

    A report of harassment or exhaustion can sit among the other answers until the final report.

Context. Since 26 May 2026, Brazil's NR-1 regulation includes psychosocial risk factors in the occupational risk management that companies must run. A climate survey does not meet that requirement on its own, but open comments often show these risks early. This is context, not legal advice. Read NR-1 on the Ministry of Labor website (Portuguese).

The solution

A flow that treats every comment as sensitive data, from submission to dashboard.

  • Anonymization first

    Rules and a list of names from IBGE replace personal data with placeholders such as PESSOA and CPF. In local mode, a small name recognition model adds to the search. The original text is never stored.

  • Two ways to run

    The demo runs on Cloudflare: Workers AI classifies with Gemma 4 26B A4B and receives anonymized text only. Organizations that cannot let anything leave their premises use the local mode, with Gemma 4 E2B on Ollama, on their own server's CPU.

  • Dashboard with a minimum group

    No group with fewer than 5 answers is shown. Small areas are merged so nobody can be identified by subtraction.

  • Critical case alerts

    When the model or the risk lexicon points to harassment, discrimination, burnout or threats, the system records an alert with the anonymized text only. In local mode, n8n notifies the person in charge on Telegram and sends a daily summary. In the demo, the Worker can forward the case to an n8n webhook.

How it works

The live demo runs entirely on Cloudflare, with no server of its own. Every answer goes through fixed rules and a language model. The legend shows the kind of each part. Name recognition exists only in local mode, and n8n comes in after the alert.

Legend

  • RULE Fixed rule: patterns, word lists and check digits. Always gives the same result.
  • NER Small model: recognizes names of people and places with spaCy. Local mode only.
  • LLM Language model: reads the anonymized text and returns labels in a fixed format. In the demo, Gemma 4 26B A4B on Workers AI. In local mode, Gemma 4 E2B on Ollama.
  • N8N Automation: n8n workflows. In local mode they send the alerts and a daily summary and delete old submissions. In the demo, n8n only receives critical cases through a webhook, when one is set up.

The diagram as text

  1. Answer The answer reaches the Cloudflare Worker with a score from 0 to 10, area, tenure and an optional comment. Before that, Turnstile checks that the sender is not a bot.
  2. Rules in the Worker RULE Inside the Worker, patterns and check digits find Brazilian documents (CPF, CNPJ, RG, CEP), email addresses, phone numbers, plates, employee IDs and addresses. Lists from IBGE, the Brazilian statistics office, find names of people and places. Each finding becomes a placeholder such as PESSOA, and the original text is dropped here.
  3. Names and places NER Local mode only. A small spaCy model finds names of people and places the rules miss. The demo has no such step, so place names slip through more easily.
  4. Risk lexicon RULE Explicit phrases about harassment, violence or self-harm flag the case as critical, even if the model fails. The flag is dropped only when both model readings say it is not a critical case.
  5. Workers AI LLM The Worker sends only the anonymized text to Workers AI, where Gemma 4 26B A4B (@cf/google/gemma-4-26b-a4b-it) returns themes, sentiment and a first critical flag. In local mode, the same prompt runs on Gemma 4 E2B with Ollama, on the server's CPU.
  6. Second reading LLM With any sign of risk, the model reads the comment again, focused on critical cases. When in doubt, the case stays flagged.
  7. D1 database The result is stored in D1, Cloudflare's database: anonymized text, labels and timings. Public submissions are deleted after 30 days. In local mode, the database is SQLite on the server itself.
  8. Dashboard The dashboard shows only groups with 5 or more answers.
  9. Alert N8N A critical case becomes an alert recorded in D1, with the anonymized text only. When an n8n webhook is set up, the Worker forwards the alert to it.

Local mode

  • Runs with docker compose on the organization's own server. No comment leaves its infrastructure.
  • Anonymizes with the same rules and IBGE name list, plus spaCy name recognition.
  • Classifies with Gemma 4 E2B on Ollama, on the server's CPU, without a GPU.
  • n8n sends the alerts on Telegram, writes a daily summary and deletes old submissions.
  • The published analysis of the synthetic dataset and the CPU timing come from this mode.

How the calculation works
  • Comments per year = answers × share with a comment × cycles.
  • Manual work = comments × (reading minutes + anonymization minutes) ÷ 60.
  • Review with the system = comments × reviewed share × minutes per review ÷ 60.
  • Hours saved = manual work minus review. Machine time uses the measured mean per comment and does not count as people's work.

Privacy

The demo was designed to keep as little as possible.

  • The comment is anonymized inside the Cloudflare Worker, before it reaches the model. The original text is never stored.
  • Cloudflare states that it does not use this content to train models and does not keep what goes through the model after the response.
  • Processing and the database are outside Brazil, on Cloudflare.
  • IP addresses are never written to the database. Only a daily code, deleted the next day, to count distinct people.
  • Public submissions are deleted after 30 days, and groups with fewer than 5 answers are not shown on the dashboard.
